# Deploying Blinked to Render at oopsiblinked.com

Everything in the repo is ready: the app builds into a Docker image that has been
tested end to end, including that data survives a restart. What remains is
creating accounts, buying a domain, and pasting in secrets — steps that need your
payment details and identity.

Work through the phases in order. Each says clearly whether **you** do it or
whether it happens automatically.

**Running cost:** about **$8.25/month** (Render Starter $7 + 5 GB disk $1.25),
plus **$10–15/year** for the domain, plus Anthropic API usage. Resend is free at
this volume.

## Phase 3 — Get the API keys (you)

Three services. Collect all the values before starting Phase 4.

### Resend — for the sign-in emails
1. Sign up at <https://resend.com> (free tier: 3,000 emails/month).
2. **Domains → Add Domain →** `oopsiblinked.com`. Resend shows DNS records
   (DKIM/SPF). Add them at your registrar, then click Verify. This can take a
   few minutes to propagate.
3. **API Keys → Create API Key** with *Sending access*. Copy it — shown once.
4. Decide your from-address, e.g. `Blinked <signin@oopsiblinked.com>`.

> Skipping domain verification? Resend's `onboarding@resend.dev` works for
> testing but only sends to your own address, so real users cannot sign in.

### Anthropic — for the AI features
You already have a working key in `.env.local`. Either reuse it or create a
separate production key at <https://console.anthropic.com/settings/keys> —
separate keys are better, since you can revoke one without breaking the other.

### Google — for "Continue with Google"
You already have a client ID. It needs the production domain added:
1. <https://console.cloud.google.com/apis/credentials> → your OAuth 2.0 Client ID.
2. Under **Authorized JavaScript origins**, add both:
   - `https://oopsiblinked.com`
   - `https://www.oopsiblinked.com`
3. Save. Changes can take a few minutes to take effect.

Keep `http://localhost:3000` in the list so local development keeps working.

## Phase 4 — Create the Render service (you)

1. Sign up at <https://render.com> and connect your GitHub account.
2. **New → Blueprint**, choose the repository. Render reads `render.yaml` and
   proposes a web service with a 5 GB disk attached — no manual configuration.
3. It will prompt for the four secrets marked `sync: false`:

   | Key | Value |
   | --- | --- |
   | `ANTHROPIC_API_KEY` | your Anthropic key |
   | `GOOGLE_CLIENT_ID` | ends `.apps.googleusercontent.com` |
   | `RESEND_API_KEY` | starts `re_` |
   | `EMAIL_FROM` | `Blinked <signin@oopsiblinked.com>` |

   `SESSION_SECRET` is generated by Render and must never be changed
   afterwards — changing it signs everyone out.
4. **Apply**. The first build takes 3–5 minutes (it compiles `better-sqlite3`).
5. When it finishes you get a URL like `blinked.onrender.com`.
   Open it and confirm the site loads.

---

## Phase 5 — Point the domain at it (you, with my DNS values)

1. In Render: **your service → Settings → Custom Domains → Add**. Add both
   `oopsiblinked.com` and `www.oopsiblinked.com`.
2. Render shows the exact DNS records. They will look like:

   | Type | Name | Value |
   | --- | --- | --- |
   | `A` | `@` | an IP address Render gives you |
   | `CNAME` | `www` | `blinked.onrender.com` |

   Use the values **Render shows you**, not these examples.
3. Add those at your registrar's DNS panel.
4. Wait for propagation (usually minutes, occasionally hours). Render issues a
   free TLS certificate automatically once it sees the records — you do not need
   to configure HTTPS.

Once the domain resolves, verify TLS, redirects, headers and the full sign-in
flow against the live site.

---

## Phase 6 — Verify

Once it is live, check:

- HTTPS works and HTTP redirects to it
- the session cookie is `Secure` + `HttpOnly` (the app sets this in production)
- email sign-in delivers a real email and the code is **not** in the response
- Google sign-in completes against the production origin
- AI scheduling and image cleanup work with the production key
- uploads survive a redeploy
- the public availability page loads for a signed-out visitor

## Prepaid analysis credit (Stripe) — optional, you

Photographers top up credit on Stripe's hosted Checkout page and each workflow analysis is charged
what it actually costs to run. Until these three steps are done, billing is simply off and
analyses are free.

1. **Account and key.** Create a Stripe account at <https://dashboard.stripe.com>. Start in
   **test mode** (the toggle at the top). Developers → API keys → copy the **Secret key**
   (`sk_test_…`) → Render → blinked → Environment → `STRIPE_SECRET_KEY`.
2. **Webhook.** Developers → Webhooks → Add endpoint →
   `https://oopsiblinked.com/api/billing/webhook`, event **`checkout.session.completed`** →
   copy the **Signing secret** (`whsec_…`) → Render → `STRIPE_WEBHOOK_SECRET`. Save; Render
   restarts with billing on.
3. **Try it.** Smart Photographer → Credit → Add $5. On Stripe's test page use card
   `4242 4242 4242 4242`, any future date, any CVC. You land back on the Credit page and the
   $5.00 appears within a few seconds (the webhook adds it, not the landing page).

To take real money, repeat 1–2 with the **live** keys (Stripe asks for business details first),
and put a refund/terms line somewhere visible — credit is prepaid and spent on running analyses,
not on the goods or services they price.

## Texting the Smart Photographer (Twilio) — optional, you

Lets a photographer text their assistant from their phone and get short replies back, and lets
the assistant text them. Only the photographer's own verified number is ever texted.

1. **Create a Twilio account** at https://www.twilio.com/try-twilio and buy a number with SMS.
   Two things to know for US numbers: a **trial** account can only text numbers you have
   verified in the Twilio console (fine for testing yourself) and prefixes every text with a
   trial notice; and once upgraded, a local (10DLC) number needs **A2P registration** before
   it will deliver to US mobiles, while a **toll-free** number needs a shorter verification
   form. Toll-free is the quicker route for a small app.
2. **Set the keys on Render** (Environment): `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` (both on
   the Twilio console home page) and `TWILIO_FROM_NUMBER` in E.164, e.g. `+15551234567`.
3. **Point the number at the app**: Twilio console → Phone Numbers → your number → Messaging
   configuration → "A message comes in": **Webhook**, `https://oopsiblinked.com/api/sms/twilio`,
   **HTTP POST**. Save. Every post is checked against Twilio's signature, so nothing else can
   pretend to be a text.
4. **Verify your mobile** under Smart Photographer → Texting: enter the number, type the
   six-digit code that arrives. Then text the Twilio number anything.

Costs: about a cent per text segment each way. The assistant sends at most 30 texts a
photographer a day, and replies are cut at about three segments.

## After launch

**Back up the disk.** The SQLite database and every uploaded wedding photo live
on that one Render disk. Render's paid plans include disk snapshots — turn them
on. Losing a client's photos is not a recoverable mistake.

**Watch the Anthropic bill.** Each photo scan plus its cleanup plan costs a few
cents. Set a spend limit in the Anthropic console.

**Scaling limits.** SQLite on one disk means one instance — do not scale to
multiple instances, as they cannot share the database file. That is fine well
past a beta; if you outgrow it, the move is Postgres plus object storage.

**Uploaded photos are personal data.** Once real couples are in there, you have
GDPR/CCPA obligations: a way to delete someone's data on request, and a privacy
policy. Worth sorting before real clients use it.
